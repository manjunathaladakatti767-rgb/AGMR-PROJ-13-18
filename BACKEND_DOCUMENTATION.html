AccessShield Backend Specs

Version: 1.0.0 | Architecture: Microservices-based API

1. System Architecture

The AccessShield ecosystem utilizes a dual-backend architecture to separate user management from heavy security analysis.

  • Main API (Port 5000): Handles Authentication, Dashboard state, and MongoDB Atlas data persistence.
  • Safety Engine (Port 5001): Dedicated Node.js service for heuristic URL analysis and scoring.
  • Database: MongoDB Atlas (Cloud) using Mongoose ODM.

2. API Reference - Main Backend (5000)

Authentication

POST /api/auth/register

Registers a new user and generates a JWT session token.

POST /api/auth/login

Authenticates user credentials and returns user profile + token.

History Management

GET /api/history

Fetches all safety reports for the authenticated user (sorted by date).

POST /api/history

Saves a new scan result to the user's permanent history logs.

DELETE /api/history/:id

Deletes a specific history record from the database.

3. API Reference - Safety Engine (5001)

POST /check-url

The core security endpoint. Runs a URL through 16 heuristic rules and returns a 0-100 risk score.

4. Database Models (Schemas)

History Schema

{
  user: ObjectId (ref: 'User'),
  url: String,
  status: 'SAFE' | 'SUSPICIOUS' | 'DANGEROUS',
  riskScore: Number (0-100),
  reasons: [String],
  recommendation: String,
  createdAt: Date
}

5. The 16-Rule Scoring Logic

The backend calculates risk using weighted penalties:

Risk Factor Penalty Detection Logic
No HTTPS +30 Checks protocol string
Homograph Attack +50 Regex check for Unicode characters
Raw IP usage +25 Detects IP patterns in hostname
Double Extension +40 Scans for patterns like .pdf.exe

7. Security Implementation

  • JWT Authentication: Secure session management using jsonwebtoken.
  • Bcrypt Hashing: Password encryption using 10 salt rounds.
  • CORS Protection: Restricted access to verified frontend origins.
  • Protected Routes: Middleware verification for all sensitive data access.
